# plc-fb-scaffold — standard FB + safety FFB + FSEQ bridge + tags

Builds the per-device logic skeleton. Requires `plc-connect`. Writing F-blocks is
proven to work in V17 **only when the safety program is open / logged in for editing**
(see `plc-knowledge`). Always reduce a REAL exported block — never hand-author network
XML (malformed FBD/F XML does not get rejected, it CRASHES TIA).

## The chain (how it wires together)

```
DEVICE (AML)     physical modules + IO byte addresses
   |
PLC TAGS         one named global tag per channel (%I / %Q bit)
   |
STANDARD FB      reads query (-BG) tags, commands output (-MB) tags;
                 carries FSEQ (std side) + GLOB (standard global bus)
   |  (handshake through a safe SDB — NOT a direct FB->FFB wire)
SAFETY FFB       gates release (RELEASE_* + QBAD), exchanges via the FSEQ
                 STD<->FS UDT pair, returns released outputs into the
                 device's FAILSAFE module band; carries SAFE_GLOB
```

The standard and safety FBs **never wire directly**. They exchange through a paired
UDT in a safe data block (the **FSEQ bridge**):
- a `STD->FS` UDT — written by the standard FB, read by the FFB;
- a `FS->STD` UDT — written by the FFB, read by the standard FB.

Two parallel global buses run alongside: `GLOB` (standard) and `SAFE_GLOB` (safety).

## Build recipe (proven, reusable)

1. **Tags.** PLC tags in V17: `PlcTagTableComposition.Create(name)` makes a table;
   `PlcTagComposition.Create(name, dataTypeName, "%I<addr>.<bit>")` makes a tag with its
   address in one call. Convention = one tag table per station, named like the station.
   Make the script idempotent (create table if missing, add only missing tags).
   - *** Command outputs go on the STANDARD output module, NOT the failsafe module.
     Putting a standard command on the failsafe band triggers "log in to the safety
     program" and is wrong by design — a safety module cannot command motion. Use the
     standard output band for command tags; the failsafe band only for safe outputs. ***

2. **Reduce a real standard FB / safety FFB.** Export a real block, keep ONE instance +
   its one network, repoint operands by SINGLE-component string swaps (byte-safe), and
   regenerate nothing inside the FlgNet. Use whitespace-tolerant regex for multi-component
   `<Access>` edits (real XML has newlines between `<Component>` tags) and dump the final
   operand list to verify.

3. **The FSEQ bridge DB is a STANDARD DB** (not F) even though it holds F-UDT members —
   that's how std↔FS data crosses the boundary. The bridge member is typed as the WHOLE
   FSEQ struct so the standard FB takes the whole thing and the FFB takes `.STD->FS` /
   `.FS->STD`.

4. **Typed "DB of UDT" objects** export as `InstanceDB` with `<InstanceOfName>` +
   `AutoNumber=false` + a fixed `<Number>`. To clone: rename the BLOCK name only (NOT the
   InstanceOfName), set `AutoNumber=true`, drop the fixed `<Number>` → no clash on import.

5. **Adding a call to an existing FB:** declare a minimal self-closing multi-instance
   member (`<Member Name="MyInst" Datatype="&quot;DEV_xxx_FB&quot;" />` — do NOT copy the
   real member's nested body), add a new CompileUnit with a non-colliding block-level ID
   (FlgNet UIds are local per-network so they don't clash), insert before the target
   network.

6. **GRAPH note:** GRAPH FBs cannot be multi-instances — call via `Scope="GlobalVariable"`;
   TIA auto-creates the instance DB on import. GRAPH→SCL is not possible; read GRAPH
   structurally from XML.

7. **Import order:** standard DBs → safety DBs → FFB → FB (`ImportOptions.Override`).
   Recompile DB before FB. Let the user compile + save once in TIA.

## Global-tag vs DB-member gotcha

A PLC tag in a tag table is referenced in FlgNet by a SINGLE
`<Component Name="TagName" />` (Scope="GlobalVariable"); a DB member needs TWO components
(DB then member). Repointing a hardware operand from a fake DB to a global tag = drop the
DB component.

## Template

`scripts/scaffold_notes.md` — a checklist + the import-order skeleton. The actual block
XML must be generated by reducing the user's REAL exported blocks at build time (it is
device- and library-specific and is never stored in the plugin).
